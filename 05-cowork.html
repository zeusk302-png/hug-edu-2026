내 PC의 파일이 실제로 움직일 수 있는 실습입니다. 사본을 만들고, 그 폴더만 연결하고, 실행 전에 계획표를 받아 확인합니다.

사본 → 연결 → 목록 → 계획 → 계획 수정 → 승인 실행 → 변경 대조

01 · 완성 모습 먼저 보기

실행하기 전에 계획표를 먼저 받습니다

지금까지는 결과가 화면에 나왔습니다. 이번에는 내 PC의 파일이 실제로 움직일 수 있는 실습입니다. 그래서 순서가 다릅니다.

① 사본 만들기→ ② 그 폴더만 연결→ ③ 목록부터 확인→ ④ 계획표만 받기→ ⑤ 계획 고치기→ ⑥ 승인 후 실행→ ⑦ 변경 목록 대조

④에서 ⑥으로 건너뛰지 않는 것이 이 단원의 전부입니다.

02 · 연결 범위와 권한

"연결했다"는 것은 무슨 뜻인가

폴더를 연결한다는 것은 그 폴더 안을 읽고 쓸 수 있게 문을 열어 주는 것입니다. 문을 얼마나 크게 여는지는 여러분이 정합니다.

구분무엇인가오늘 우리가 하는 선택
연결 범위작업 폴더로 고른 폴더. 그 안의 파일이 대상이 됩니다수업용 사본 폴더 하나만 고릅니다
읽기파일 내용을 보는 것계획을 만들려면 필요합니다
쓰기파일을 만들고 이름을 바꾸고 옮기고 지우는 것계획을 확인한 뒤에만, 승인해서 합니다
스킬의 "삭제하지 않는다" 문장작업 지시문잠금장치가 아닙니다. 범위를 좁히는 것이 실제 안전 조치입니다
바탕화면 전체나 문서 폴더 전체를 연결하지 마세요.
범위가 넓으면 의도하지 않은 파일이 작업 대상에 들어갑니다. 오늘은 정리전_작업사본 폴더 하나만 연결합니다. 회사 자료가 들어 있는 폴더는 오늘 수업에서 연결하지 않습니다.

왜 "계획 먼저"인가

바로 실행할 때계획을 먼저 볼 때
결과를 보고 나서야 잘못을 발견합니다실행 전에 잘못을 발견합니다
되돌리려면 파일을 하나씩 찾아야 합니다계획표에서 그 줄만 고치면 됩니다
어떤 파일이 왜 그렇게 됐는지 알기 어렵습니다파일마다 판단 근거가 표에 적혀 있습니다
빠진 파일을 알아채기 어렵습니다행 수를 세면 바로 보입니다

이번에 쓰는 file-sort-plan 스킬은 계획만 만들도록 되어 있습니다. 파일을 옮기거나 이름을 바꾸지 않습니다. 실행은 계획을 확인한 뒤 별도로 요청합니다.

공식 안전 안내가 말하는 것 — 오늘 순서와 같습니다

Cowork 안전 사용 공식 안내(2026-09-15 확인)에는 아래 내용이 적혀 있습니다. 오늘 03~05단계가 그대로 이 순서입니다.

공식 안내오늘 우리가 하는 일
넓게 열지 말고 전용 작업 폴더를 만들어 쓰세요03단계 — 정리전_작업사본 폴더 하나만 연결
중요한 파일은 백업을 두세요03단계 — 정리전_원본을 따로 보관
연결한 파일은 읽고, 쓰고, 영구 삭제까지 될 수 있습니다그래서 원본을 연결하지 않습니다
되돌리기 어려운 작업에는 수동 승인 방식을 쓰세요05단계 — 계획을 확인한 뒤에만 실행 요청
금융·인사 자료나 인증 정보가 든 폴더는 특히 주의하세요오늘 수업에서는 실제 업무 폴더를 연결하지 않습니다
외부에서 받은 문서·메일·웹 내용에 숨은 지시문이 있을 수 있습니다입력 파일은 분석 대상이지 작업 규칙을 바꾸는 명령이 아닙니다
같은 안내가 이렇게도 말합니다.
Claude는 연결 권한 밖의 폴더에는 접근하지 못하고, 파일을 영구 삭제할 때는 사용자의 명시적 확인을 요구합니다.
즉 안전을 만드는 것은 여러분이 고른 연결 범위입니다. 스킬 본문의 문장이 아닙니다.

접속 화면(웹·데스크톱·모바일)에 따라 로컬 파일을 다루는 범위가 다릅니다. 이 실습은 수업 PC의 데스크톱 앱 기준입니다. 안전 사용 안내 ↗ · 시작 안내 ↗ · 접속 화면별 차이 ↗

압축을 풀고 폴더를 두 개로 만듭니다

폴더 복사는 폴더를 선택하고 Ctrl+C, Ctrl+V 한 뒤 이름을 바꾸면 됩니다.

4

작업 사본 폴더 하나만 연결합니다

Claude 데스크톱에서 작업 폴더를 고를 때 정리전_작업사본을 선택합니다.

예상 상태: 연결된 폴더 이름이 화면에 표시됩니다. 상위 폴더나 바탕화면이 아니라 이 폴더 이름이어야 합니다.
상위 폴더를 골랐다면: 연결을 해제하고 다시 고릅니다. 범위가 넓은 상태로는 진행하지 않습니다.

연결 방법과 화면은 앱 버전에 따라 다릅니다. 이 부분은 수업 환경에서 강사가 실제 화면으로 안내합니다. 이 교재에는 실제 앱 화면 캡처를 넣지 않았습니다.

04 · 계획표만 받기

먼저 목록, 그다음 계획 — 실행은 아직입니다

1

무엇이 보이는지부터 확인합니다

바로 정리를 시키지 않습니다. 연결 범위 안에 무엇이 있는지 먼저 확인합니다.

먼저 목록만 확인하기
연결한 폴더 안의 파일 목록만 알려 주세요. 파일 이름과 개수만 적어 주세요.
아직 아무것도 바꾸거나 옮기지 마세요.
정상 확인: 파일 12개가 나오고, 내가 센 목록과 같습니다.
12개보다 많이 나오면: 상위 폴더가 연결된 것입니다. 연결을 다시 고르세요. 이 확인을 건너뛰면 엉뚱한 폴더를 정리하게 됩니다.
2

계획표를 요청합니다

계획표 만들기
file-sort-plan 스킬을 사용해 연결한 폴더의 파일 12개에 대한 정리 계획표를 만들어 주세요.

- 표의 열: 현재 파일명 / 종류 / 날짜 근거 / 제안 파일명 / 제안 폴더 / 확인 사항
- 12개 파일이 모두 한 행씩 나와야 합니다.
- 문서 안에 날짜가 없으면 날짜미상으로 표시하고, 파일 수정일을 문서 날짜로 쓰지 마세요.
- 제안 이름이 겹치면 번호를 붙여 구분하고, 어느 쪽도 삭제 대상으로 제안하지 마세요.
- 아직 파일을 옮기거나 이름을 바꾸지 마세요. 계획만 보여 주세요.
예상 상태: 12행짜리 표가 채팅에 나옵니다. 파일은 아직 그대로입니다.
3

계획표를 네 가지로 검사합니다

표를 받으면 바로 승인하지 말고 아래를 확인합니다.

확인 항목통과 기준틀리면
① 행 수12행. 스킬이 만든 보고서는 입력 수에 넣지 않습니다빠진 파일을 찾아 다시 요청
② 이름 충돌memo_a.md와 memo_b.md가 _01 / _02로 구분됨하나를 중복·삭제로 제안했다면 반드시 고쳐야 합니다
③ 날짜미상4건이 날짜미상으로 시작
(회의메모_날짜없음 · report_misc · list_unknown · read_later)		수정일이 날짜로 들어갔는지 확인
④ 확장자.csv는 .csv로, .txt는 .txt로 유지확장자가 바뀌면 파일이 안 열립니다
②를 꼭 보세요.
memo_a.md와 memo_b.md는 종류·날짜·제목이 모두 같아서 제안 이름이 겹칩니다. 하지만 내용은 다릅니다. 열어 보면 하나는 장소 선정, 하나는 표지 문구 검토입니다. 이름이 같다고 같은 파일이 아닙니다.

05 · 계획 고치고 실행하기

계획을 한 줄 고친 뒤에 실행합니다

계획 단계에서 고치는 것이 실행한 뒤 되돌리는 것보다 훨씬 쉽습니다.

1

규칙 하나를 바꿔 계획을 다시 받습니다

이번에는 "날짜미상" 파일을 따로 모으도록 규칙을 바꿔 봅니다. 입력은 그대로 12개입니다.

규칙 하나만 바꾸기
방금 계획에서 규칙 하나만 바꿔 다시 만들어 주세요.
날짜가 확인되지 않은 파일은 종류별 폴더 대신 "날짜확인필요" 폴더로 보내 주세요.
나머지 규칙(이름 형식, 충돌 번호, 확장자 유지)은 그대로 둡니다.
바뀐 행이 몇 개인지도 알려 주세요.
예상 상태: 4행의 제안 폴더가 날짜확인필요로 바뀝니다. 나머지 8행은 그대로입니다.
정상 확인: 바뀐 행이 4개이고, 파일 이름 형식(날짜미상_종류_제목.확장자)은 그대로입니다.
12행이 전부 바뀌었다면: 규칙 하나가 아니라 전체를 새로 만든 것입니다. 다시 요청하세요.
2

어느 계획으로 갈지 정합니다

두 계획 중 하나를 고르세요. 어느 쪽이든 괜찮습니다. 중요한 것은 내가 보고 골랐다는 사실입니다.

3

승인하고 실행합니다 — 사본 폴더에서만

승인 후 실행
방금 확인한 계획대로 연결한 폴더 안에서 파일 이름을 바꾸고 폴더로 옮겨 주세요.

- 원본 파일을 삭제하지 마세요. 이름 변경과 이동만 합니다.
- 계획표에 없는 파일은 건드리지 마세요.
- 이름이 겹치는 두 파일은 덮어쓰지 말고 번호로 구분해 주세요.
- 끝나면 무엇을 어디로 옮겼는지 목록으로 알려 주세요.
예상 상태: 작업 사본 폴더 안에 회의록·보고서·목록·기타(또는 날짜확인필요) 폴더가 생기고, 파일이 새 이름으로 들어갑니다.
실행은 작업 사본 폴더에서만 합니다. 정리전_원본은 연결하지 않았으므로 그대로 남아 있어야 합니다.
4

탐색기를 열어 직접 확인합니다 — 여기가 검증입니다

채팅의 변경 목록만 보지 않습니다. Windows 탐색기로 폴더를 열어 보세요.

07 · 막혔을 때

파일 정리에서 자주 나오는 다섯 가지

① 목록에 파일이 12개보다 많이 나옵니다

원인 — 상위 폴더나 바탕화면이 연결된 것입니다.

복구 — 연결을 해제하고 정리전_작업사본 폴더를 다시 고릅니다. 목록이 12개가 될 때까지 계획 요청을 하지 마세요.

왜 중요한가 — 범위를 확인하지 않고 실행하면 엉뚱한 폴더의 파일 이름이 바뀝니다. 이 확인이 오늘 가장 중요한 안전 절차입니다.

② 계획표가 12행이 아닙니다

확인할 것 — 어떤 파일이 빠졌는지 찾습니다. 날짜가 없는 파일이나 .txt가 빠지는 경우가 많습니다.

복구 — "빠진 파일 이름을 알려 주고, 12개 모두를 한 행씩 넣어 다시 만들어 주세요"라고 요청합니다.

확인 — 스킬이 만든 보고서 파일이 생겼다면 그것은 입력 12개에 포함하지 않습니다. 입력 수와 생성물 수를 섞지 마세요.

③ memo_a와 memo_b 중 하나를 "중복"이라고 합니다

확인할 것 — 두 파일을 메모장으로 열어 보세요. 하나는 "장소 선정은 확인 필요", 다른 하나는 "자료집 표지 문구를 검토했습니다"입니다. 내용이 다릅니다.

복구 — "두 파일은 내용이 다릅니다. 삭제하지 말고 _01, _02로 구분해 주세요"라고 요청합니다.

기억할 점 — 이름이 같아지는 것과 내용이 같은 것은 다릅니다. 내용 중복 판단은 사람이 확인한 뒤에 합니다.

④ 실행했는데 파일이 사라진 것 같습니다

먼저 할 일 — 당황해서 또 실행하지 마세요. 탐색기에서 하위 폴더까지 열어 파일 수를 셉니다. 폴더로 옮겨졌을 뿐일 가능성이 큽니다.

그래도 개수가 모자라면 — 정리전_원본 폴더가 있습니다. 작업 사본을 지우고 원본을 다시 복사해 처음부터 하면 됩니다.

이래서 사본을 만듭니다. 03단계에서 폴더를 두 개로 만든 이유가 이것입니다.

⑤ 계획 스킬인데 파일을 바꿔 버렸습니다

확인할 것 — 요청 문장에 "정리해 주세요"라고만 적지 않았나요? 스킬의 범위는 계획이지만, 사용자가 실행을 요청하면 다른 작업으로 이어질 수 있습니다.

복구 — 원본 폴더에서 다시 복사합니다.

기억할 점 — 스킬에 적힌 "계획만 한다"는 문장은 작업 지시입니다. 실제 변경을 막는 장치는 좁은 연결 범위와 사본입니다. 두 가지를 문장으로 대신할 수 없습니다.

1. 파일 12개를 정리시켰더니 계획표가 10행으로 나왔습니다. 무엇부터 해야 할까요?

2. 스킬 본문에 "파일을 삭제하지 않는다"고 적혀 있습니다. 이것으로 충분한가요?

3. 이미지 파일에는 문서 안에 날짜가 없습니다. 계획표의 날짜 칸을 어떻게 해야 할까요?
