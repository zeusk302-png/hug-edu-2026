# 검토기준 · 예시 (따라잡기용)

시나리오 C에서 시범 2건으로 정한 내용을 파일로 적은 **예시**입니다. 정상 경로는 조에서 직접 적는 것이며, 이 파일은 시범 단계를 건너뛴 조가 합류할 때 씁니다. 이 파일은 검토 대상 문서가 아니므로 제출서류 20건과 **다른 폴더**에 두고, 첨부할 때는 20건과 함께 넣되 표에 행으로 들어가면 안 됩니다.

## 열 이름과 순서
문서번호 / 파일명 / 제목 / 배포 형태 / 자료 수 / 제출일 / 배포 예정일 / 담당 역할 / 판정 / 판정 이유 / 근거 위치 / 유사 문서

## 판정 조건
- 교육 기준 충족: 제목·배포 형태·자료 수·일정(제출일·배포 예정일)·담당 역할 다섯 칸이 모두 있고, 문서 안의 날짜가 서로 어긋나지 않음
- 확인 필요: 한 칸이라도 비었거나, 두 표의 날짜가 어긋나거나, 배포 예정일이 제출일보다 빠르거나, "이전 버전" 표시가 있음
- 읽기 불가: 글자를 읽을 수 없어 판정 자체가 불가능함(문서번호·파일명은 적고 행은 남김)

## 누락 항목 처리
값이 없는 칸은 비워 둔다. 0이나 추측값을 넣지 않는다. 판정 이유에 "○○ 칸 비어 있음"이라고 적는다.

## 날짜 충돌 처리
신청 항목 표의 배포 예정일과 진행 일정 표의 배포일이 다르면 두 값을 모두 적고(예: 2026-06-10 / 진행 일정 표 2026-06-17) 판정은 확인 필요.
배포 예정일이 제출일보다 빠르면 확인 필요.

## 유사 문서·이전 버전 처리
"이전 버전" 표시가 있는 문서는 표에 남기고 확인 필요로 판정한다. 유사 문서 열에 상대 문서번호를 적는다. 어느 쪽이 최종본인지는 이 문서들만으로 판단하지 않는다.

## 근거 위치 적는 방식
"1쪽 신청 항목 표", "1쪽 진행 일정 표", "1쪽 상단 띠"처럼 실제로 볼 수 있는 위치를 적는다. 쪽 번호·좌표를 지어내지 않는다.

## 나눠서 처리할 때
첨부 제한으로 나누면 두 묶음 모두 이 파일을 함께 첨부하고, 합친 뒤 S01~S20이 각 한 번씩 있는지 센다. 유사 문서 열은 합친 뒤 다시 확인한다.

이 기준은 교육용 가상 자료를 위한 것이며 실제 심사 기준이 아닙니다.
