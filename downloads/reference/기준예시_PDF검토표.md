# 기준 예시 · 실제 Claude 실행 결과가 아닙니다

수업에서 결과를 비교할 때 쓰라고 작성한 예시입니다. 문장 표현이 같아야 정답인 것은 아니며, 근거와 규칙을 지켰는지가 기준입니다.

종합실습 시나리오 C · 입력: 제출서류 PDF 20건 → 비교 검토표

정답 전체는 `comparison-reference.csv`에 있습니다. 판정값은 **이 수업이 정한 교육용 기준**이며 실제 심사·보증·법률 판단이 아닙니다.

## 교육용 판정 기준 (다섯 칸)
제목 / 배포 형태 / 자료 수 / 일정(제출일·배포 예정일) / 담당 역할.
- 다섯 칸이 모두 있고 문서 안의 날짜가 서로 맞으면 → **교육 기준 충족**
- 한 칸이라도 비었거나 날짜가 어긋나면 → **확인 필요**
- 글자를 읽을 수 없어 판단 자체가 불가능하면 → **읽기 불가**

## 숫자로 먼저 확인할 것
| 항목 | 값 |
|---|---|
| 입력 문서 | 20건 |
| 교육 기준 충족 | 12건 |
| 확인 필요 | 7건 |
| 읽기 불가 | 1건 |

확인 필요 7건의 내역: 필수 항목 누락 3건(S13·S14·S15), 날짜 충돌 2건(S16·S17), 이전 버전 표시 2건(S18·S19).

## 판정이 갈리는 지점
| ID | 무엇이 걸리나 | 근거 위치 |
|---|---|---|
| S13 | 담당 역할 칸이 비어 있음 | 1쪽 신청 항목 표 |
| S14 | 자료 수 칸이 비어 있음 | 1쪽 신청 항목 표 |
| S15 | 배포 예정일 칸이 비어 있음 | 1쪽 신청 항목 표 |
| S16 | 신청 항목의 배포 예정일 2026-06-10, 진행 일정 표의 배포일 2026-06-17 | 1쪽 두 표를 함께 봐야 보임 |
| S17 | 배포 예정일 2026-05-15가 제출일 2026-05-21보다 빠름 | 1쪽 신청 항목 표 |
| S18 | S04와 제목·내용이 같고 "이전 버전" 표시가 있음 | 1쪽 상단 띠 |
| S19 | S07과 제목·내용이 같고 "이전 버전" 표시가 있음 | 1쪽 상단 띠 |
| S20 | 자료 수와 배포 예정일이 번져 읽히지 않음 | 1쪽 신청 항목 표 |

## 흔한 실수
- **S18·S19를 표에서 빼 버리기.** 유사 문서는 표시만 하고 제외하지 않습니다. 어느 쪽이 최신인지는 이 문서들만으로 알 수 없습니다.
- **S20의 빈칸을 0이나 추측값으로 채우기.** 읽지 못한 칸은 비우고 상태를 읽기 불가로 둡니다. 문서번호와 파일명은 읽을 수 있으므로 행 자체는 남깁니다.
- **S16을 정상으로 넘기기.** 신청 항목 표만 보면 문제가 없어 보입니다. 같은 쪽의 진행 일정 표와 맞춰 봐야 합니다.
- **20건을 한 번에 요청하고 표만 받기.** 먼저 2건으로 열 구성을 맞춘 뒤 전체를 처리해야 열이 중간에 바뀌지 않습니다.
