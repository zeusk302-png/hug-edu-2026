# 정리 규칙 · 예시 (따라잡기용)

05 단원 06단계에서 "다음에도 쓸 정리 규칙"을 파일로 적은 **예시**입니다. 정상 경로는 학생이 계획표를 검토하며 정한 내용을 직접 적는 것입니다. 이 파일은 정리 대상 폴더 **밖**에 둡니다(연결한 폴더 안에 두면 정리 대상에 섞입니다).

## 이름 형식
YYYY-MM-DD_종류_짧은제목.확장자. 문서 안에서 날짜를 확인할 수 없으면 날짜미상_종류_짧은제목.확장자. 파일 속성의 수정일을 문서 날짜로 쓰지 않는다.

## 폴더
회의록 / 보고서 / 목록 / 기타. 날짜가 확인되지 않은 파일은 종류별 폴더 대신 **날짜확인필요** 폴더로 보낸다. (05단계에서 바꾼 규칙)

## 이름 충돌
제안 이름이 같아지면 원래 파일명 오름차순으로 _01, _02를 붙인다. 이름이 같다는 이유로 내용 중복으로 판단하거나 삭제하지 않는다.

## 확장자
원래 확장자를 그대로 둔다(.csv는 .csv, .txt는 .txt, .png는 .png).

## 예외 처리
- 읽을 수 없는 파일: 계획표에 "읽기 불가"로 남기고 옮기지 않는다.
- 내용이 모호해 종류를 정할 수 없는 파일: 기타로 두고 확인 사항에 이유를 적는다.
- 같은 이름의 파일이 목적 폴더에 이미 있으면 덮어쓰지 않고 접미번호를 붙인다.

## 실행 순서
① 목록만 확인 → ② 계획표(입력 수 = 행 수) → ③ 사람이 확인·수정 → ④ 승인 뒤 실행(이름 변경·이동만, 삭제 없음) → ⑤ 탐색기에서 개수·원본 확인.
계획표를 만드는 스킬(file-sort-plan)은 실행하지 않는다. 실행은 승인 문장으로 따로 요청한다.

## 산출물 개수
입력 파일 수와 새로 생긴 파일(계획표·작업 기록)은 따로 센다. 입력 12개 + 기록 1개 = 폴더 안 13개일 수 있다.

교육용 가상 자료를 위한 규칙입니다.
